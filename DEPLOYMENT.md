# Hosting and Apple distribution

Deploy the Node backend as a normal Node24 process/container with native process execution, the target platform's optional Claude SDK native package, writable temporary space and outbound Anthropic HTTPS. Install dependencies on the target OS/architecture; Windows node_modules must not be copied to a Linux server. Build with `npm ci`, `npm run setup` and `npm run build`; use `npm start` under your process supervisor. The backend loads its module-relative `.env` when present, and environment variables override it. Production secrets should come from your secret manager, not images or the Apple bundle.

The API defaults to loopback. For container hosting bind API_HOST=0.0.0.0 and expose it only through a controlled HTTPS ingress. Add actual end-user authentication, authorization, per-user quotas and rate limits before exposing model execution remotely. CORS and knowledge of a URL do not authenticate native clients. Do not embed Anthropic keys or a permanent shared service credential in Swift. This edition intentionally has no pretend mobile-secret authentication flow.

Configure ingress to allow POST SSE without buffering, no-transform caching and a timeout longer than the180-second SDK deadline. Node flushes headers and relays safe message/error/done events with backpressure. Browser/native disconnect closes the response pipeline and aborts owned SDK work. Only a typed final result followed by done completes successfully at the transport level; a failed SDK result remains a UI error. Configure optional ALLOWED_ORIGINS only for exact browser origins you intend to allow.

Node bounds actual input32KiB and trimmed prompts1–4000UTF-16 units. Each run owns temporary work/home/config directories with tools/settings/skills/MCP/plugins/session persistence disabled, a scrubbed child environment and key redaction. These restrictions are not an OS or network sandbox. Do not grant the Node host access to unrelated private workloads. Only approved public SDK fields enter API responses; raw thinking, private paths, session identifiers and tool payloads are omitted.

Debug Apple builds permit development HTTP via their separate Info-Debug.plist. Release uses Info-Release.plist without arbitrary-load exceptions and rejects non-HTTPS API settings. Mac builds have app sandbox and outgoing-network entitlements. Test the release build against your HTTPS origin before distribution. Select your Apple development team and unique bundle identifier in Xcode; add your own icons, signing/distribution configuration and privacy disclosures for publication. This task does not publish to App Store, create cloud infrastructure, or perform paid model inference.
